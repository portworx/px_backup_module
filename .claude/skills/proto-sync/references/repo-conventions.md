# purepx.px_backup collection — conventions that matter for proto-sync

All paths relative to `ansible-collection/`.

## Layout

```
galaxy.yml                      # namespace purepx, name px_backup, version (3.1.1 on main; read it)
ansible.cfg                     # library=./plugins/modules, module_utils=./plugins/module_utils, inventory=./inventory/hosts
meta/runtime.yml                # requires_ansible >=2.10
README.md
plugins/
  modules/<m>.py                # backup, backup_schedule, backup_location, cloud_credential, cluster,
                                # restore, resource_collector, rule, role, schedule_policy,
                                # volume_resource_only_policy, receiver, recipient, log_level,
                                # cluster_discovery_config, auth  (ls plugins/modules for truth)
  module_utils/px_backup/api.py # PXBackupClient(api_url, token, validate_certs, ca_cert, client_cert, client_key)
                                #   .make_request(method, endpoint, data=None, cert=None, params=None)
docs/
  README.md                     # module index + "integrates with PX-Backup API vX" + inventory tree
  common/ssl_configuration.md
  modules/<m>.md                # handwritten markdown, one per module
examples/
  auth/auth.yaml                # shared token fetch, included by every playbook
  output_handler/main.yaml      # shared result printer/saver
  <m>/<op>.yaml                 # create / update / delete / inspect_one / inspect_all / ...
  combined/                     # multi-module playbooks (scheduled_backup etc.) — update if a new
                                # required param lands in a module they call
inventory/
  hosts                         # [local] localhost ansible_connection=local ; [common] localhost
  group_vars/common/all.yaml    # px_backup_api_url, px_backup_token, org_id, pxcentral_*, ssl_config, output_config
  group_vars/<m>/<op>[_vars].yaml   # list variable consumed by examples/<m>/<op>.yaml
  group_vars/combined/{combined,scheduled_backup}.yaml
```

Vars file naming per module (verified):

| module | pattern |
|---|---|
| backup_schedule, cloud_credential | `create_vars.yaml`, `update_vars.yaml`, `inspect_vars.yaml`, `enumerate_vars.yaml`, `delete_vars.yaml` (+ `enumerate_post_request.yaml`, `update_owner_vars.yaml`) |
| everything else | `create.yaml`, `update.yaml`, `inspect.yaml`, `enumerate.yaml`, `delete.yaml` (+ op-specific: `update_ownership.yaml`, `validate.yaml`, `share.yaml`, `retry_backup.yaml`, `get_backup_resource_detail.yaml`, `attach_vro_backup_schedule.yaml`, `validate_smtp.yaml`) |

Some release/topic branches carry standalone helper scripts at `ansible-collection/*.py`
(`main.py`, `update_schedules.py`, `retry-failed-backups.py`, ...). They call the API
directly and are **not** part of the collection. Out of scope unless the user names them.

No tests dir, no CHANGELOG, no Makefile, no CONTRIBUTING. Docs are not generated by
antsibull/ansible-doc; edit markdown by hand. `ansible-doc` and `ansible-playbook` are
installed on this box; `ansible-lint` is not.

## Module anatomy (backup.py / backup_schedule.py as reference)

```python
from ansible.module_utils.basic import AnsibleModule
from ansible_collections.purepx.px_backup.plugins.module_utils.px_backup.api import PXBackupClient

BACKUP_OBJECT_TYPE_MAP = {'Invalid': 0, 'All': 1, 'VirtualMachine': 2}   # enum string -> wire int

DOCUMENTATION = r'''
---
module: backup
short_description: ...
version_added: "2.10.0"
options:
    operation:
        choices: [CREATE, UPDATE, DELETE, INSPECT_ONE, INSPECT_ALL, ...]
    api_url: {required: true, type: str}
    token:   {required: true, type: str}
    name: ...
    org_id: ...
    <field>:
        description: ...
        type: dict
        required: false
        version_added: '2.9.0'        # per-option tag used for newer fields
        suboptions:
            name: {type: str}
            uid:  {type: str}
'''
EXAMPLES = r''' ... '''   # backup.py has it; backup_schedule.py does not
RETURN   = r''' ... '''   # backup.py has it (backup, message, changed); backup_schedule.py does not

def build_backup_request(params):            # name varies: backup_schedule_request_body(module)
    metadata = {"name":..., "org_id":..., "uid":...}
    request = {"metadata": metadata}
    if params.get('operation') == 'UPDATE':  # UPDATE sends a reduced body
        ...
        return request
    request.update({...required-ish fields...})
    if params.get('backup_type'):
        request['backup_type'] = {'Invalid':0,'Generic':1,'Normal':2}.get(params['backup_type'], 2)
    optional_fields = ['cluster', 'pre_exec_rule_ref', ..., 'backup_schedule_ref']
    for field in optional_fields:
        if params.get(field) is not None:
            request[field] = params[field]
    return request

def run_module():
    module_args = dict(
        operation=dict(type='str', required=True, choices=[...]),
        api_url=dict(type='str', required=True),
        token=dict(type='str', required=True, no_log=True),
        ...
        <field>=dict(type='dict', required=False, options=dict(name=dict(type='str'), uid=dict(type='str'))),
        # Deprecated

        ssl_config=dict(type='dict', required=False, options=dict(...)),
    )
    module = AnsibleModule(argument_spec=module_args, supports_check_mode=True)
```

Endpoints are string literals, e.g.:

| op | call |
|---|---|
| create | `client.make_request('POST', 'v1/backup', data=body)` |
| update | `PUT v1/backup` |
| inspect all (GET) | `GET v1/backup/{org_id}` with `params={'enumerate_options.max_objects': ..., 'backup_location_ref.name': ...}` (flattened dotted keys) |
| inspect all (POST) | `POST v1/backup/{org_id}/enumerate` with JSON body |
| inspect one | `GET v1/backup/{org_id}/{name}` (+ `uid` query) |
| delete | `DELETE v1/backup/{org_id}/{name}` or `POST v1/backup/{org_id}/delete` for bulk/extra params |

Response processing (`process_backup_response`) copies all keys of `metadata` /
`backup_info` generically. New response fields therefore flow through without code
changes; only `RETURN` + docs need updating.

## Wire format facts (verified in px-backup-api)

- Swagger (`pkg/apis/v1/api.swagger.json`) uses **proto snake_case names** as JSON keys. No `json_name`.
- `(gogoproto.jsontag)` only changes the Go struct tag; does not change REST JSON key.
- Nested message definitions flatten: `BackupInfo.Volume` → `BackupInfoVolume`.
- `google.protobuf.Timestamp` → `{"type":"string","format":"date-time"}`.
- Enums → swagger `string` with `enum: [...]` of value names, but **px-backup server accepts ints** and the modules send ints via `*_MAP`. Check sibling module before changing that.
- Leading proto comment attaches only to the first field after it; later fields get no swagger description. When writing docs, pull description from the proto comment, not swagger.
- Deprecation is comment-only (`// ... deprecated, not to be used.`); fields are never removed/reserved.

## Naming quirks to respect (do not "fix" in a sync PR)

- `inventory/group_vars/backup/create.yaml` vs `inventory/group_vars/backup_schedule/create_vars.yaml` — per-module inconsistency. Read `vars_files` in the example playbook for truth.
- `inventory/group_vars/common/all.yaml` (READMEs say `all.yml`).
- `ssl_config.px_central` in all.yaml/auth.yaml vs `ssl_config.pxcentral` in docs.
- Some docs tables still list `validate_certs` top-level though modules take `ssl_config`.
- `backup_schedule.py` `INSPECT_ALL_POST_REQUEST` branch references undefined `params` when
  `volume_resource_only_policy_ref` is set (NameError). Pre-existing; mention, don't fix silently.
- Known argument_spec-only (undocumented) params as of 2026-10-01, from the drift check:
  - `backup_schedule`: `backup_location`, `cloud_credential`, `cluster`, `delete_backups`, `schedule_policy` (deprecated string refs)
  - `restore`: `backup_object_type`, `cluster_name_filter`, `cluster_uid_filter`, `include_detailed_resources`, `max_objects`, `name_filter`, `owners`, `replace_policy`, `status`
  - `backup`: none
  Don't report these as new drift; report only deltas vs this list.

## Drift check (run after edits)

```bash
cd ansible-collection && python3 - <<'EOF'
import re, yaml, ast, sys
m = sys.argv[1] if len(sys.argv) > 1 else 'backup'
src = open(f'plugins/modules/{m}.py').read()
doc = yaml.safe_load(re.search(r"DOCUMENTATION = r'''(.*?)'''", src, re.S).group(1))
doc_opts = set(doc['options'])
# crude: collect top-level keys of module_args = dict( ... )
body = re.search(r"module_args\s*=\s*dict\((.*?)\n    \)", src, re.S).group(1)
spec_opts = set(re.findall(r"^\s{8}(\w+)\s*=\s*dict\(", body, re.M))
print("in DOCUMENTATION only:", sorted(doc_opts - spec_opts))
print("in argument_spec only:", sorted(spec_opts - doc_opts))
EOF
```

## Example playbook idiom

```yaml
            # Optional parameters
            <field>: "{{ item.<field> | default(omit) }}"
```

Lists/dicts that the module treats as required-ish use `default([])` / `default({})`.
Always keep `ssl_config: "{{ ssl_config.px_backup | default({}) }}"` as last param.
